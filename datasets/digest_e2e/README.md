# digest_e2e dataset

Inputs and expected properties for the free-only digest entrypoint E2E
(`integrations/digest_agent/live_e2e.yaml` and `live_e2e_replay.yaml`).
See `docs/digest-e2e.md` for the service matrix, credentials, metrics,
and exact commands.

## Files

| File | Kind | Provenance |
|---|---|---|
| `github_activity.json` | recorded GitHub activity | Real `GET /repos/amagarzogonzalo/eval-service/pulls/10` and `/files` (2026-10-20), patches truncated to 1,200 chars. Public data; no credentials. |
| `llm_fixture.json` | synthetic Groq-compatible response | Hand-written deterministic fixture for offline replay. **Not live evidence.** It returns a digest-like section with a `PASS` verdict so the real orchestrator can complete its review loop. |
| `output_metrics_replay.json` | observed output metrics | Generated by the real entrypoint replay run; outer metrics only, inner metrics `n/a`. |

## Cases and expected properties

`live_e2e.yaml` (live, never in CI):

1. **`e2e-free-only-preflight`** — static scan of digest config plus a
   fake-transport test of the target's `build_llm_provider`: exactly the
   reviewed free Groq candidates, no paid route. No network/model.
2. **`e2e-entrypoint-fail-closed`** — the real entrypoint with no
   provider key. Must exit nonzero (`No LLM provider configured`) and
   record `failure_class=no_llm_provider`; no PDF/email.
3. **`e2e-entrypoint-live-success`** — real `python -m digest_agent.main`
   with real GitHub, free Groq models, real PDF, real SMTP. Two trials;
   expects success, PDF, one email with PDF, free-only flags, and `n/a`
   inner metrics.
4. **`e2e-entrypoint-live-bad-repo`** — real 404 repository; expects
   `github_error`, no PDF/email, no model call.

`live_e2e_replay.yaml` (offline, safe for CI):

- **`e2e-free-only-preflight`** — same static/fake-transport check.
- **`e2e-entrypoint-replay-success`** — real entrypoint, fixture GitHub
  and Groq responses, real PDF and SMTP sink. Expects success, PDF,
  email, observed request counts (GitHub/model), zero paid attempts,
  model `openai/gpt-oss-120b`, inner metrics `n/a`.
- **`e2e-entrypoint-replay-bad-repo`** — fixture 404; expects
  `github_error`, no PDF/email, zero model requests.

## Refreshing the GitHub fixture

Use a read-only token; never write it to a file or the repository:

```sh
TOKEN=$(aws ssm get-parameter --name /eval/github_watch_token \
  --with-decryption --query Parameter.Value --output text)
curl -s -H "Authorization: Bearer $TOKEN" \
  https://api.github.com/repos/amagarzogonzalo/eval-service/pulls/10
```

Keep the shape used by `replay_sitecustomize.py`
(`repos[].pull_requests[]` and `commits[]`). Truncate patches; do not
record diffs from private repositories or any credential.

## Free-only budget and cadence

- The entrypoint receives only `GROQ_API_KEY` with the target's fixed
  free-tier candidates. All other provider keys are removed.
- No paid call is possible; rate limits/exhaustion fail closed.
- Timer: daily at 04:10 UTC with up to 300 s jitter
  (`eval-live-digest.timer`); `flock` prevents overlap; `--workers 1`.
- Replay: offline, no key, no network, no budget.
- Live requires a free-tier Groq key from the operator environment
  (`/etc/eval/digest-groq.env` on the VM); none is committed.
